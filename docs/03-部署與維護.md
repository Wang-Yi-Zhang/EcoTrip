# 03 GitHub Pages 部署與使用維護

## A. 部署到 GitHub Pages

這個網站只有一個 `index.html`，沒有建置步驟，也不需要伺服器。

### 1. 建立 GitHub Repository

1. 登入 GitHub，點右上角 **＋ → New repository**。
2. Repository name 例如 `sabah-2027`。
3. 選 **Public**。免費帳號的 GitHub Pages 需要公開 repo，所以 `index.html` 裡的內容（含業者報價）任何人都看得到。請勿放入個資、護照號碼或訂位代號。
4. 不用勾選任何初始化選項，按 **Create repository**。

### 2. 上傳檔案

**方法 A：網頁上傳**（最簡單）

1. 在 repo 頁面點 **Add file → Upload files**。
2. 把 `index.html`、`sw.js`（離線支援，必須和 `index.html` 放在同一層）、`README.md`、`docs/`、`gas/`、`tools/` 整批拖進去。`.github/` 資料夾（自動測試）用網頁上傳不容易，建議改用方法 B。
3. 按 **Commit changes**。

**方法 B：用 git**（本資料夾已是本機 git repo）

```bash
git remote add origin https://github.com/<你的帳號>/sabah-2027.git
```

```bash
git branch -M main
```

```bash
git push -u origin main
```

### 3. 開啟 GitHub Pages

1. 進入 repo 的 **Settings → Pages**。
2. Source 選 **Deploy from a branch**。
3. Branch 選 `main`，資料夾選 `/ (root)`，按 **Save**。

### 4. 取得公開網址

1 到 2 分鐘後，Pages 頁面上方會顯示 `https://<你的帳號>.github.io/sabah-2027/`。打開這個網址就能使用，分享給旅伴即可。

> 每位旅伴的設定（人數、勾選、備註）各自存在自己的瀏覽器裡，不會同步。要共享設定時，請一個人用「⚙ 資料／匯出 → 匯出規劃 JSON」，其他人再匯入。

### 5. 更新資料

- **改內建資料**：編輯 `index.html` 裡對應的 `data-*` 區塊，再 commit。可以直接在 GitHub 網頁上按鉛筆圖示編輯。存檔後約 1 分鐘生效，若沒更新請強制重新整理（Ctrl+F5）。
- **不想改程式碼**：用 Google 試算表加 GAS（見下方 D.5），網站設定為讀取遠端資料。

## B. 本機預覽與測試

- 直接用瀏覽器打開 `index.html` 就能用。行程、試算、物種介紹、清單都能離線運作；地圖圖磚和 iNaturalist 查詢需要網路。
- 核心邏輯單元測試（需要 Node.js 18 以上）：

```bash
node docs/tests/core.test.mjs
```

## C. 使用方式

| 分頁 | 用途 |
|---|---|
| 總覽 | 8 個決策問題的即時回答、KPI、風險、檢查摘要 |

## D. 維護

### D.1 更新行程

編輯 `data-itinerary`：

- 改活動內容：修改 `title`、`detail`、`slot`、`type`、`effort`。
- 已和業者確認的活動：把 `status` 改成 `"confirmed"`。
- 取得確切的交通時間後：填入 `duration_h` 和 `duration_basis`（例如 `"業者 2026-12-01 回覆"`）。沒查證的時間不要填。
- 新增可選安排：在 `options` 加入 `{ "label": "…", "cost_ref": "<費用 id 或 null>" }`。
- 訂房確認後：把該日的 `lodging_status` 改成 `"confirmed"`。

改完打開網頁看「行程品質檢查」，確認沒有新的錯誤。

### D.2 修改價格

編輯 `data-costs.items`：

- 取得正式報價：`price` 填數字，`status` 改 `"quoted"`，並在 `data-sources` 新增來源（業者、日期），把來源 id 放進 `source_ids`。
- 還沒報價：`price: null`、`status: "unquoted"`。**不要填 0。**
- 估算：`price: {"low":…, "mid":…, "high":…}`、`status: "estimate"`，並且一定要寫 `assumption`。
- 臨時試算：不必改檔案，直接在網頁的費用明細點「編輯」，結果只存在你的瀏覽器。

### D.3 新增物種

在 `data-species.items` 新增一筆，欄位見 `docs/02`。

1. `inat_taxon_id`：用 `https://api.inaturalist.org/v1/taxa?q=<學名>` 查到的 `id`，必須是整數。
2. `iucn.status`：查 IUCN 紅色名錄或 iNaturalist taxon 頁面，並填 `checked_on`。
3. `records.tabin`／`records.danum`：文獻有紀錄才填 `"recorded"` 並附 `lit_source`；沒有查證就填 `"unknown"`。
4. 敏感物種（例如穿山甲）設 `"sensitive": true`。
5. 希望預設列入目標清單，就設 `"flagship": true`。

### D.4 修改地圖 POI

編輯 `data-locations.pois`：

- 座標用十進位度數（`lat`、`lng`）。
- 沒有可靠來源時保留 `"approximate": true`，地圖會用虛線外框標示。
- `type` 決定顏色與篩選類別；`region` 影響夜數計算（住宿點一定要正確填）。
- iNaturalist 查詢範圍在 `areas`：
  - 有經查證的 Place ID 時，設 `place_usable: true`。
  - 否則使用 `bbox`，並保留 `bbox_is_approximate: true`。

### D.5 設定 GAS Endpoint

1. 建一份空白 Google 試算表。
2. 選單 **擴充功能 → Apps Script**，貼上 `gas/Code.gs` 的內容並存檔。
3. **自動建立欄位**：在 Apps Script 編輯器上方的函式選單選 `setupSheets`，按「執行」。第一次執行需要授權，範圍應只有目前這份試算表。完成後試算表會有：
   - `costs` 工作表：完整欄名。`category`、`unit`、`status`、`applies`、`price_currency`、`when`、`qty_*_from` 都是下拉選單，價格與數量欄只接受非負數字，`default_on` 是核取方塊。滑鼠移到表頭可以看到各欄說明。
   - `json` 工作表：`dataset`（下拉選單）與 `json` 兩欄。
   - 首列凍結；表頭有「編輯前警告」，可以改，但會先跳出提醒。
4. 填資料（把內建費用一次貼進去，不用手打）：
   - 在專案資料夾執行 `node tools/sheet-export.mjs`，會產生 `gas/costs-for-sheet.tsv`（含表頭列，欄位順序與 `setupSheets()` 建立的相同）。
   - 用記事本開啟這個檔案，全選、複製；到試算表的 `costs` 工作表點 A1 儲存格，貼上。
   - 貼完後執行 `node tools/sheet-export.mjs --check <你的 /exec 網址>`。它用和網站相同的規則驗證端點，並比對試算結果；顯示「完全相同」才算貼對。
   - 之後要改價格，直接改試算表的儲存格即可，網站重新整理後生效。
   - `costs` 每列一個費用項目。網站讀到遠端 costs 時會**整份取代**內建費用，所以要填**全部**項目，不能只填要修改的那幾列。漏掉行程會用到的項目（例如 `night_safari`）時，網站會因參照錯誤拒收，並回退內建資料。
   - 行程、物種等較深的資料集，放在 `json` 工作表，整份 JSON 貼在一格。
5. **部署 → 新增部署作業**：
   - 類型：網頁應用程式
   - 執行身分：**我**
   - 誰可以存取：**任何人**
6. 按「部署」並授權，複製結尾是 `/exec` 的網址。
7. 回到網站，點右上「⚙ 資料／匯出」，貼上網址，先按 **測試連線**，成功後再按 **使用遠端資料**。
8. 右上角狀態會顯示「資料：遠端 GAS」。設定視窗會列出每個資料集來自本機還是遠端。

**`setupSheets()` 的行為**

- 只由擁有者在編輯器手動執行。它**不會**被網站或公開網址觸發；公開端點 `doGet` 維持唯讀。
- 可以重複執行：工作表已存在就沿用；只把缺少的欄名加到最右邊；既有欄位的順序、資料列，以及旅伴自己加的備註欄都不動；資料驗證規則會重新套用。
- 網站只讀 `COSTS_HEADERS` 定義的欄位，其他欄位都當作備註，可以隨意新增。
- 已填的值若不在下拉清單內，不會被刪除，但儲存格會出現紅色三角形提示，請改成清單內的值。

**維護規則**

- 網站（`index.html` 的 `validateDataset`）新增欄位或允許值時，請同步更新 `Code.gs` 開頭的 `ALLOWED` 與 `COSTS_HEADERS`，再重新執行 `setupSheets()`，並到「管理部署作業 → 編輯 → 新版本」發布。
- 改完執行 `node docs/tests/gas.test.mjs`：它會用模擬試算表檢查兩件事，一是下拉允許值和網站驗證規則一致，二是把內建費用寫進試算表、經 `doGet` 回傳後，試算結果和內建資料完全相同。
- 單格上限 50,000 字元：`json` 工作表的 species 壓縮後約 40,000 字元（2026-11 實測）。大量新增物種前請先確認長度；測試裡也有這項檢查。

**授權範圍（最小權限）**

- `Code.gs` 第一行的 `/** @OnlyCurrentDoc */` 讓腳本只申請 `spreadsheets.currentonly`：只能存取它所綁定的這一份試算表，不能碰你帳號裡的其他試算表。授權時，畫面上的權限說明應只涉及「這個應用程式所在的試算表」。如果說明是存取你**所有**的 Google 試算表，表示這一行被刪掉或沒有放在檔案開頭。也可以在 Apps Script 編輯器的「總覽」頁查看「專案 OAuth 範圍」，應只有 `spreadsheets.currentonly`（實際畫面文字以 Google 當時介面為準）。
- 這行必須保留在檔案開頭。腳本必須綁定在試算表上（從試算表的「擴充功能 → Apps Script」建立），程式只能用 `getActiveSpreadsheet()`，不能改用 `openById()`。
- 端點維持唯讀：不要加入寫入呼叫或 `doPost`。
- 試算表本身**不需要**分享給任何人；公開的只有網頁應用程式網址回傳的資料。
- 如果先前曾用沒有這一行的版本授權過，可以到 Google 帳號的「安全性 → 第三方存取權」撤銷該專案，再重新授權並部署新版本。
- 本專案刻意**不放** `appsscript.json`，讓 Apps Script 依程式碼自動判斷範圍。將來新增需要其他權限的功能時，Google 會跳出新的授權畫面讓擁有者確認，不會悄悄擴權。

**CORS 說明（請務必閱讀）**

- 存取權設為「任何人」時，GAS 會回應 302 並轉址到 `script.googleusercontent.com`。轉址後的回應允許跨網域讀取，瀏覽器的 `fetch` 可以直接讀到 JSON。
- 網站只送單純的 GET 請求，不帶自訂 header，所以不會觸發 CORS 預檢（preflight）。
- 以下情況瀏覽器會擋下，網站會顯示錯誤並回退到內建資料：
  - 存取權設成「僅限自己」或「任何擁有 Google 帳戶的使用者」：這時 GAS 會回應登入頁 HTML。
  - 使用 `/dev` 測試網址，或貼錯網址。
- 前端無法繞過 CORS。如果你們的 Google Workspace 管理員禁止「任何人」存取，可改用下列做法：
  - 把 JSON 檔放在同一個 GitHub repo 裡（同網域），或
  - 改用其他允許 CORS 的靜態託管。
- 修改 GAS 程式後要 **管理部署作業 → 編輯 → 版本：新版本**，網址不變；只按存檔不會生效。

**資料狀態**

- 遠端讀取失敗、但之前成功讀過時，網站會改用上次的遠端快取，狀態顯示「資料過期」。
- 從未成功讀過時，網站會使用內建資料。

### D.6 確認 iNaturalist 查詢成功

1. 在「目標物種」點任一物種的「詳細與 iNat 紀錄」。
2. Tabin 和 Danum 兩格各自顯示狀態：
   - **即時查詢成功**：剛從 API 取得。
   - **快取（24 小時內）**：沿用先前結果，不重複請求。
   - **查無研究級紀錄**：API 正常，但沒有符合的紀錄（不代表物種不存在）。
   - **查詢失敗**：會附上錯誤原因，例如離線、HTTP 429、逾時。
   - **資料過期**：更新失敗，顯示舊快取。
3. 點「iNaturalist 搜尋結果」可以在官網看到同條件的完整紀錄，用來對照筆數。
4. 想強制重新查詢：按「重新查詢」，或在「⚙ 資料／匯出」清除 iNaturalist 快取。
5. 請求頻率：所有請求依序排隊、間隔至少 1.1 秒；遇到 HTTP 429 會自動退避重試。

## E. 授權與歸屬

- **地圖**：OpenTopoMap（CC-BY-SA）、OpenStreetMap 貢獻者。歸屬文字已顯示在地圖右下角。
- **物種照片**：來自 iNaturalist，只顯示帶有 CC 授權碼的照片，並在照片上標示作者與授權。
- **觀測資料**：iNaturalist API。研究級資料仍可能有誤，也不代表完整分布。
