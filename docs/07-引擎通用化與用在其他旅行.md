## 2. 資料格式的變更（以程式為準）

### 2.1 原本寫死在程式、現在放在資料裡的

| 位置 | 欄位 | 說明 |
|---|---|---|
| `trip` | `currency: {base, home, symbols, default_rates}` | `base` 本位幣（必填）；`home` 旅客結算幣別（沒有就填 `null`，介面不顯示換算）；`default_rates` 其他幣別對本位幣的預設匯率 |
| `trip` | `regions: {<key>: 顯示名稱}`、`transit_region` | 行程每天的 `region`、地點的 `region` 都必須是這裡的 key |
| `trip` | `choices: [{id, label, default, compare_category?, options: [{key, label, lodging}]}]` | 選擇題。行程的 `lodging` 可以填選擇題的 id；有 `compare_category` 的會出現在費用試算與方案比較 |
| `trip` | `pax_rules: [{below, level, msg}]` | 人數低於某值時的提醒 |
| `trip` | `storage_prefix`、`legacy_state`、`legacy_export_schemas`、`short_title`、`subtitle`、`default_rooms` | 瀏覽器儲存鍵的前綴、舊版設定鍵名對照、頁首文字 |
| `costs` | `categories: {<key>: 顯示名稱}` | 費用分類，順序即顯示順序 |
| `costs` | `quoted_label`、`toggle_labels: {flights, extras}` | 介面文字 |
| `costs.items[]` | `applies` | 內建值 `always`／`flights`／`extras`／`optional`；其他值視為選擇題的選項 key（選到才計入） |
| `costs.items[]` | `when` | `singles`，或 `plan_<選項 key>` |
| `costs.items[]` | `qty.nights_from: "activity_count"`、`count_label`、`quoted_nights` | 晚數＝行程中選到這個費用項目的活動數；與報價晚數不同時提醒 |
| `costs.items[]` | `days_check: {segment, msg}` | 報價天數少於該區段的日曆天時提醒；`msg` 可用 `{span}`、`{days}` |
| `costs.compare` | `choice`、`criteria[].default_weight` | 這份比較對應哪個選擇題 |
| `locations.areas[]` | `short` | 觀測範圍的短名稱 |
| `species` | `group_label`；`records` 的 key 必須涵蓋所有 `areas[].key` | 不再限定兩個地區 |

### 2.2 新增的資料

```json
// essentials.tasks：待辦與期限
{ "id": "book_tabin", "title": "Tabin 下訂並付訂金",
  "due": null,                 // YYYY-MM-DD；null＝期限未知（不是沒有期限）
  "due_kind": "external",      // external＝對方規定；self＝自訂目標日
  "due_basis": "報價信沒有訂金期限", "consequence": "報價可能失效",
  "depends_on": ["ask_tabin"], "source_ids": ["src_quote_a"] }

// itinerary.connections：需要算餘裕的銜接
{ "id": "c-d6-brl", "day": 6, "option": "brl", "title": "…", "buffer_min": 30,
  "depart":   { "time": "07:00", "status": "tbc", "label": "從 Tabin 出發" },   // status 不是 confirmed 時不會顯示為「足夠」
  "legs":     [{ "label": "Tabin → Lahad Datu", "duration_h": 1.5, "basis": "官方" }],
  "deadline": { "time": "09:30", "label": "BRL 排程車出發" },
  "missing":  ["集合地點與報到截止時間"] }

// itinerary.days[].contingencies：每日備案表
{ "sign": "徵兆", "trigger": "觸發條件", "decider": "誰決定", "fallback": "備案",
  "extra_cost": { "amount": null, "currency": "USD", "note": "未知時 amount 填 null，不要填 0" } }
```

### 2.3 使用者狀態與匯出

- LocalStorage 鍵：`<trip.storage_prefix>.v1`（沙巴仍是 `ecotrip2027.v1`，舊設定會自動轉換）。
- 狀態新增 `choices`、`rates`、`actuals`、`riskLog`；移除 `danumPlan`、`lastNight`、`fxUsd`。待辦勾選存在 `checklist["task:<id>"]`。
- 匯出檔 `schema: "ecotrip-export/1"`，新增 `trip_id`、`actuals`、`risk_log`、`tasks`、`connections`。舊的 `ecotrip2027-export/1` 仍可匯入。
- GAS 信封 `schema: "ecotrip/1"`（原為 `ecotrip2027/1`；尚未有任何已部署的端點，所以直接改名）。

## 3. 怎麼用在另一趟旅行

1. 複製 `docs/tests/fixtures/contrast-trip.json` 當範本，改成新行程的 7 個資料集（`trip`、`itinerary`、`costs`、`species`、`locations`、`sources`、`essentials`）。沒有物種就留 `"items": []`，物種分頁會自動隱藏；沒有方案二選一就留 `"choices": []`，比較分頁會自動隱藏。
2. 產生網頁（資料有錯會列出原因，不會產生檔案）：

```bash
node tools/build-trip.mjs 我的行程.json 我的行程.html
```

3. 把產生的 html 改名為 `index.html`，連同 `sw.js` 放到新的 repo 部署。
4. 如果要用 Google 試算表更新費用：把產生的檔案放回 `index.html` 的位置後執行下面的指令，它會依新行程的分類、幣別、選項重寫 `gas/Code.gs` 的下拉選單。

```bash
node tools/gas-allowed.mjs --write
```

**不需要改的東西**：`core-js`、`ui-js`、`sw.js`。如果發現非改不可，代表引擎還有沒抽乾淨的假設，請把那個情況加進 `contrast-trip.json` 再改。

**目前引擎仍然假設的事**（新行程不符合時要先擴充）：

- 每房最多 2 人為基準（單人房、三人房的判斷以此計算）。
- 「機票」與「其他費用」兩個開關是固定的兩組。
- 情境固定為低／中／高三種。
- 介面文字是繁體中文。
- 物種分頁的資料來源是 iNaturalist。
